# Daymark

Daymark 是一个面向个人使用的本地优先日程与项目工作台。它把月历、个人任务、项目子任务和笔记放在同一个桌面应用里，适合需要自己规划课程、作业、项目和日常安排的学生或个人用户。
可以导入课程日历等。

由于作者经常需要查看自己的待办事项，因此想到，在vibe coding如此发达的现在，为什么不自己搭一个呢？如果对这个项目感兴趣或者是对你有帮助，麻烦点个star！这对我很重要。

感兴趣的朋友也可以来访问我的博客：[https://hangchen.pages.dev/](https://hangchen.pages.dev/)

当前版本：`0.6.1`

## 它解决什么问题

Daymark 用一个本地应用整理三类信息：

- **日程**：按月查看日历事件，并在当天详情中查看时间线。
- **我的任务**：管理不属于某个项目的个人待办、截止日期、预计完成时间和任务笔记。
- **项目**：按“计划中、进行中、已完成”管理项目；每个项目下面单独维护子任务。

它适合单人使用，不要求注册账号，也不依赖云端服务。数据默认保存在当前电脑上。

## 主要功能

### 日历与日程

- 月历视图和当天详情视图
- 当前时间线，帮助判断当天接下来要做什么
- 支持从 `.ics` 文件一次性导入日历或课程表
- 月份箭头、月份选择器和“今天”按钮
- 日历侧栏的“随手记”，自动保存直到你主动删除

### 任务

- 新建、编辑、删除和完成任务
- 截止日期、预计完成时间和任务笔记
- 按预计完成日期分组
- 待完成、已完成和全部筛选
- 过去一年的个人任务完成热力图
- 点击热力图日期查看当天完成的任务

### 项目与子任务

- 项目按“计划中、进行中、已完成”分栏
- 项目不再使用百分比进度，避免用一个数字假装精确反映项目状态
- 项目子任务在项目页面内单独创建和管理
- 项目拥有完成热力图
- Windows 桌面版可以关联本地项目文件夹
- 可以从项目卡片打开文件夹，或使用 VS Code 打开项目

### 本地数据与恢复

- 保存使用队列和临时文件替换，降低并发保存时的数据损坏风险
- 启动时主数据无法读取会尝试使用备份文件
- 可以从“数据与导入”导出和恢复 JSON 备份
- 桌面版按 Windows 用户分别保存数据

## 使用方式

### Windows 安装版或便携版

从 GitHub Releases 下载：

- `Daymark Setup *.exe`：安装版，适合长期安装使用
- `Daymark *.exe`：便携版，下载后直接运行

两种版本都不需要单独安装 Node.js，也不需要手动启动服务。程序会在本机启动自己的本地服务，数据保存在：

```text
%APPDATA%\Daymark\data\planner.json
```

`127.0.0.1` 是每台电脑自己的本机地址。别人下载并运行 Daymark 后，会使用对方电脑上的本地地址和本地数据，不会连接到你的电脑。

当前 Windows 安装包没有数字签名，首次运行时 Windows 可能显示“未知发布者”提示。

### 从源码运行

需要 Node.js `20.19+`：

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

然后打开：

```text
http://127.0.0.1:5173/
```

这也是本机地址，不能作为公网网站链接分享给别人。Windows 用户也可以运行根目录的 `Daymark.cmd`。

## 当前局限

Daymark 目前优先解决个人本地规划问题，以下能力尚未实现：

- 没有账号、云同步、多人协作或跨设备同步
- 没有重复任务、提醒通知和系统级日历自动同步
- `.ics` 目前是一次性导入，不会自动从 Apple Calendar、Google Calendar 或其他服务更新
- 没有撤销删除和批量编辑，删除前需要确认内容或先导出备份
- 没有自动更新机制，需要手动下载新版安装包或便携版
- 项目关联的是本地文件夹路径；文件夹移动到另一台电脑后需要重新关联
- 网页源码版不能调用本地文件夹和 VS Code 操作，只有 Windows 桌面版提供这些功能
- 目前没有数字签名，Windows 可能显示安全警告

这些限制是当前版本的实际边界，不代表数据会上传到云端。正式长期使用前，建议先导出一份 JSON 备份，并把备份保存到项目目录之外。

## 数据与隐私

Daymark 默认只监听 `127.0.0.1`，不会把日程、任务、项目或笔记上传到服务器。源码运行时数据写入项目目录下的 `data/`；桌面版写入 `%APPDATA%\Daymark\data\`。这些目录不会进入 Git 仓库，也不会包含在公开安装包中。

如果需要迁移到另一台电脑：

1. 在“数据与导入”中导出 JSON 备份。
2. 在新电脑安装或运行 Daymark。
3. 从同一位置导入备份。
4. 如果项目绑定了本地文件夹，在项目设置中重新选择文件夹。

不要把包含真实日程的 `planner.json`、备份文件或截图上传到公开 issue。
